# 移す先

READMEに置かない内容と、その移す先を示す。リポジトリにすでに文書の置き場所（`docs/`の構成、文書のサイト、wiki）があれば、そちらに従う。

| 内容 | 移す先 | READMEに残すもの |
|---|---|---|
| 任意の機能のセットアップ（OCR、外部サービスとの連携など） | `docs/<機能>.md` | 1行の説明とリンク |
| 構文・設定ファイル・環境変数・オプションの詳細 | `docs/reference.md`、`docs/configuration.md`など | 必須の設定だけ |
| OS固有の手順（常駐、自動起動、サービスへの登録） | `docs/<OS>.md` | 1行の説明とリンク |
| データの保存場所、バックアップ、移行 | `docs/data.md` | データを消す操作があれば、その注意の1行 |
| 運用（監視、更新、トラブルシューティング） | `docs/operations.md`、`docs/troubleshooting.md` | リンク |
| セキュリティ上の前提と制限 | `docs/security.md` | 外部に公開する設定などの注意の1行 |
| 脆弱性の報告先 | `SECURITY.md` | 無し（GitHubが、Securityのタブとissueを作る画面に案内を出す） |
| 開発の決まり、ビルド、テスト、リリースの手順 | `docs/development.md`（`CONTRIBUTING.md`があればそちら）。予算に収まっていても移す | 「開発」の節に1行のリンク |
| 変更の履歴 | `CHANGELOG.md`、GitHubのリリース | 無し |
| ライブラリの関数やオプションの一覧 | APIの文書（ソースのコメントから作られるもの） | APIの文書へのリンク |
| ライブラリの使用例（2つ目以降） | 言語の節が示す場所（GoはExampleテスト） | 最小の例を1つ |
| よくある質問 | `docs/faq.md` | 3項目までならREADMEに残してよい |
| 作った理由、ほかとの比較、設計 | `docs/design.md` | 2文まで |
| 実装していないこと、今後の予定 | `docs/design.md`、issue | 無し |

## 移す先のファイル

- 冒頭に、何の文書かを1文で書く。READMEの続きではなく、単独で読める文書にする
- 見出しは、ファイルの題名をH1にし、移した節をH2から始める
- 相対リンクは、移した先のファイルから見たパスに直す（`docs/`に移したら、`scripts/x.ps1`は`../scripts/x.ps1`）
- 移した内容が小さい（目安は20行未満）ときは、1つのファイルにまとめる。ファイルを細かく分けすぎない
- `docs/`のファイルが多い（目安は6つ以上）ときは、`docs/README.md`に一覧を置き、READMEからはその一覧にもリンクする

## READMEの節を参照していた箇所

READMEの節へのリンク（`README.md#…`）は、節を移すと切れる。次を探して、移した先に付け替える。

```bash
git grep -n -E 'README(\.md)?#' -- . ':!README.md'
```

コードのコメント、ほかの文書、Issueのテンプレートも探す対象に含める。
