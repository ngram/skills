# 予算の決め方

## 段階の選び方

段階は、リポジトリの大きさではなく、初めての人が使い始めるまでに要る情報の量で選ぶ。
次の手がかりを、言語の節（`lang/<言語>.md`）の「規模の手がかり」とあわせて見る。

| 手がかり | small | standard | large |
|---|---|---|---|
| 主なコマンド（初めての人が使うもの） | 1つ | 2〜3つ | 4つ以上 |
| 必須の設定（APIキー、設定ファイル、外部サービス） | 無し | 1〜2つ | 3つ以上 |
| 主な入れ方 | 1通り | 2〜3通り | OSごとに違う |
| 別の文書のサイト | — | — | 無い |

- 迷ったらstandardにする
- 文書のサイトがあるなら、largeにしない。調べた大きいプロジェクトの多くは、文書のサイトにリンクして、READMEを230行以内に収めている（[survey.md](survey.md)）
- 任意の機能、メンテナンス用のコマンド、OS固有の手順は、数に入れない。どれも移す対象である
- 選んだ段階と理由を、1〜2文で示す（例：「主なコマンドは`<名前> sync`と`<名前> serve`の2つで、必須の設定は外部サービスのAPIキーだけなので、standard（200行）とした」）

## 設定ファイル

開発者が予算を続けて使いたいときは、READMEと同じディレクトリに`.readme-budget.json`を置く。予算をREADMEの中に書かないのは、読み手に関係の無い情報をREADMEに入れないためである。

```json
{
  "preset": "standard",
  "maxLines": 250,
  "sections": { "使い方": 120, "FAQ": null },
  "keep": ["検索構文"],
  "reason": "検索構文は利用者が毎回参照するため、READMEに残す"
}
```

| キー | 値 | 意味 |
|---|---|---|
| `preset` | `small`・`standard`・`large` | 段階（全体の上限が120行、200行、300行） |
| `maxLines` | 正の整数 | 全体の行数の上限。`preset`より優先する |
| `maxProseLines` | 正の整数 | 地の文の行数の上限（既定は全体の上限の30%） |
| `maxProseWidth` | 正の整数 | 地の文の表示幅の合計の上限（既定は地の文の上限×80桁） |
| `maxSectionLines` | 正の整数 | 1つの節の行数の上限（既定は全体の上限の30%） |
| `maxCodeBlockLines` | 正の整数 | 1つのコードブロックの行数の上限（既定は15行） |
| `maxHeadingDepth` | 正の整数 | 見出しの深さの上限（既定は3） |
| `sections` | 節の見出しと、正の整数か`null`の組 | 節ごとの行数の上限。`null`は上限なし |
| `keep` | 見出しの文字列の配列 | READMEに残す節。移す候補にせず、節の上限もかけない。全体の行数には数える |
| `reason` | 文字列 | この予算にした理由。あとで見直すときに読む |
| `$comment` | 文字列 | メモ。スクリプトは読まない |

- 知らないキーや、型の違う値があれば、スクリプトは終了コード2で終わる
- `sections`と`keep`の見出しは、READMEの見出しの文字列と完全に一致させる
- 開発者の指示を設定ファイルに書くときは、`reason`にその指示の理由を書く

## 予算に収まらないとき

1. 移す候補（スクリプトの「長い節」）のうち、`keep`でない節から移す
2. 残す節の中を縮める（重なる説明、長い出力例、2つ目以降の例）
3. それでも収まらなければ、予算を上げる案を、理由とともに開発者に示す。勝手に上げない
