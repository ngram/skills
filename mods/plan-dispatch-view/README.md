# plan-dispatch-view

Skill[plan-dispatch](../../plan-dispatch/)のチームの進捗を、Claude Codeのペインに表示するmod。
チームの状態のファイル（`plan/.dispatch/<チームID>/team.json`）を数秒ごとに読み、ワーカーの状態と担当中のタスク、タスクごとの状態、全体の進み具合を表示する。

ファイルを書かず、ネットワークにも接続しない。ペインからタスクを割り当てるなどの操作はできない。ペインでできる操作は、タスクの結果の表示と、ほかのタブやタスクのファイルを開くことだけである（「結果の表示とタブへのジャンプ」）。

## 必要なもの

- Claude Code。VS Code拡張で表示するときは、拡張機能のバージョン2.1.299以降
- Skill`plan-dispatch`（このmodは、Skillが書いた`team.json`を読むだけである）

## インストール

Claude CodeのCLIでは、プロンプトに次を入力する。

```text
/plugin marketplace add ngram/skills
/plugin install plan-dispatch-view@ngram-skills
```

VS Code拡張のプロンプトでは`/plugin`を使えないので、ターミナルで次を実行する。ターミナルで入れたプラグインは、VS Code拡張でも読み込まれる。既に開いているタブにペインのコマンドが出ないときは、VS Codeのウィンドウを再読み込みする。

```bash
claude plugin marketplace add ngram/skills
claude plugin install plan-dispatch-view@ngram-skills
```

modは、利用者の権限で動くコードである。入れる前に中身を確かめるときは、リポジトリを手元に置いて`claude plugin validate mods/plan-dispatch-view`を実行する。modが呼ぶAPI（ファイルの読み取り、タイマー、ペイン、コマンド、状態、VS Codeのコマンド`code`の実行、トースト）と、使うフック（`session.start`、`command.run`、`prompt.submit`、`ui.close`、`ui.render`）が表示される。

## 使い方

- `/plan-dispatch-view`で、ペインを開く
- 自動で開く設定（`autoOpen`）が有効なら、`/plan-dispatch`（`/plan-dispatch:plan-dispatch`、`/anthropic-skills:plan-dispatch`も同じ）を呼んだタブで、ペインが自動で開く。参加のコマンド（`/plan-dispatch join <チームID> …`）で参加したタブでは、そのチームを表示する
- 招待で参加したワーカーのタブでは、Skillを呼ばないので自動では開かない。`/plan-dispatch-view`で開く

VS Code拡張では、チャットパネルの幅が800ピクセル以上ならペインが会話の横に、それより狭ければプロンプトの上に出る。狭いときは、要約（ワーカーの数、完了したタスクの数など）だけを表示する。

ペインが会話の横に出ていて、タスクに依存関係があるときは、Taskの表の下に依存関係の図を表示する。依存の無いタスクを左端に置き、依存先から矢印を引く。依存先が完了した矢印は実線、未完了の矢印は破線になる。ターミナルでは図を描けないので、表示しない。

チームのファイルは、gitのメインの作業ツリーのルートの`plan/.dispatch/`から読む（gitのリポジトリでなければ、セッションのプロジェクトのルート）。worktreeの中のタブでも、同じ場所を読む。

表示するチームは、次の順に選ぶ。

1. 参加のコマンドで参加したタブでは、そのチーム
2. そのタブのセッションが、リーダーかワーカーとして`team.json`に記録されているチーム（複数なら、`team.json`の更新時刻が最も新しいもの）

どちらにも当たらなければ、ほかのタブのチームは表示せず、「このタブのチームは、まだ作成されていません」と表示する。新しいチームを作るタブで、リーダーが`team.json`を書く前に、前のチームを表示して取り違えないようにするため。

## 結果の表示とタブへのジャンプ

ペインが会話の横に出ているときは、次の項目を押せる。リーダーのタブには全ワーカーとのやり取りが混ざるので、タスクごと、ワーカーごとの詳細を確かめるときに使う。

- Taskの行のタスクID：その行の下に、タスクのファイル（`plan/.dispatch/<チームID>/tasks/<タスクID>.md`）の「結果」の節（ワーカーが書いた要約と、変えたファイル）を表示する。もう一度押すと閉じる。開いている間は、ワーカーが結果を書き直すと表示も新しくなる。結果の下の「ファイルを開く」で、タスクのファイルをエディタで開く
- Workerの行のワーカーID：そのワーカーのタブを前面に出す。タブを閉じていれば、そのセッションを新しいタブで開く
- Teamの行のリーダーの名前：リーダーのタブを前面に出す。ワーカーのタブから、リーダーのタブへ戻るときに使う

タブとファイルを開くときは、VS CodeのCLI（`code --open-url`）を実行する。ペインのリンクはVS Codeのタブを開けないため。次のものは押せない。

- このタブ自身（リーダーのタブのリーダーの名前、ワーカーのタブのそのワーカー）
- セッションのIDが`team.json`に無いワーカー（参加を受け付ける前のワーカーと、古いバージョンのSkillで作ったチーム）
- ターミナルの画面のワーカーとリーダー（前面に出すタブが無い）。結果の表示は、ターミナルでも使える

会話の中の特定のメッセージへジャンプすることはできない。VS Code拡張のタブを開くURIには、メッセージを指定する方法が無いため。

## 設定

自動で開く設定（`autoOpen`、既定は有効）は、`/config`の画面に行として出るので、そこで変えられる。値は`settings.json`の`pluginConfigs`に保存される。

## 表示が出ないとき

- 「チームがありません」：括弧の中に示した`plan/.dispatch/`に、`team.json`がまだ無い。リーダーがチームを作ると表示される。リーダーが別の場所に書いている場合は、Skillを新しいバージョンに入れ直す
- 「このタブのチームは、まだ作成されていません」：そのタブのセッションのIDが、どの`team.json`にも無い。リーダーのタブでは、リーダーがチームを作ると表示される。ワーカーのタブでは、リーダーが参加を受け付けると表示される。古いバージョンのSkillで作ったチームは、セッションのIDを記録していないので、ずっとこの表示になる。その場合は、Skillを新しいバージョンに入れ直す
- 「modを更新してください」：Skillが書いた`team.json`の版に、このmodが対応していない。modを入れ直す
- ペインが出ない：VS Code拡張のバージョンが2.1.299より前だと、modは描画されない。Skillの動作には影響しない
- 「VS Codeのコマンドcodeを実行できません」：PATHに`code`のコマンドが無い。VS Codeのコマンドパレットで「Shell Command: Install 'code' command in PATH」を実行するか、VS Codeを入れ直してPATHに追加する。VS Code Insiders（コマンドは`code-insiders`）には対応していない
