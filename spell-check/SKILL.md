# 英単語の綴りの確認（typos）

英単語の綴りを、typos（https://github.com/crate-ci/typos）で確かめ、誤字を直す。

- typosは、よくある誤字の一覧と照らし合わせる道具で、一覧に無い誤字は見つけない。日本語の表記も確かめない
- ほかのSkillの手順から呼ばれたときは、確かめる対象と直す範囲は、呼んだSkillの決まりに従う。指摘の扱いと辞書への登録は、このSkillに従う

## 確かめる

同梱の`scripts/check_spelling.mjs`を、確かめる対象に合わせて次のどちらかで実行する。`${CLAUDE_SKILL_DIR}`はこのSKILL.mdのあるディレクトリを指す。Claude Code以外で展開されないときは、そのディレクトリのパスに置き換える。

```bash
# ステージした内容を確かめる
node "${CLAUDE_SKILL_DIR}/scripts/check_spelling.mjs" staged

# 指定したファイルを確かめる
node "${CLAUDE_SKILL_DIR}/scripts/check_spelling.mjs" files <ファイル>...
```

- `staged`は、ステージした内容をインデックスから一時ディレクトリに書き出して確かめる。作業ツリーの変更は見ない。typosの設定ファイル（`_typos.toml`など）もインデックスから読むので、設定を直したらステージしてからかけ直す
- `staged`の指摘は、「今回の変更の行」「変更していない行」「ファイル名」に分かれる。一部だけステージしたファイルには「一部だけステージ」の印が付く
- `files`は、作業ツリーのファイルを、作業ツリーのtyposの設定ファイルと一緒に一時ディレクトリに写して確かめる。ファイル名は確かめない
  - 今いるリポジトリの中のファイルには、そのファイルから最寄りの設定が効く
  - リポジトリの外のファイル（スクラッチパッドの下書きなど）には、今いるリポジトリの直下の設定が効く。下書きはスクラッチパッドに置いたままでよい
  - リポジトリの外で実行すると、設定なしで確かめる
- どちらの指摘にも、行の中身と、拡張子で分けたファイルの種類（文書かソースコードか）が添えてある。文書の中のコードブロックとインラインコードは、文書であってもコードの中として扱う
- 終了コードは、指摘が無ければ0、指摘があれば1。typosやgitが誤字以外の理由で失敗したら（設定ファイルの誤り、無いファイルなど）2で、そのときは出力をユーザーに示して止まる

### typosが入っていないとき

スクリプトは「typosが見つからないため、スペルの確認を飛ばした」と示して、終了コード0で終わる。そのときは、次のように扱う。

1. 確認を飛ばしたことをユーザーに伝え、`pip install typos`で入れるかを尋ねる。許可を得るまで入れない
2. 断られたら、確認を飛ばしたまま先に進む
3. 許可を得たら`pip install typos`を実行し、`typos --version`で確かめてから、飛ばした確認をかけ直す
4. pipが無い、またはエラーで入らないときは、出力を示し、ほかの入れ方（`cargo install typos-cli`、リリースのバイナリ）を伝えて先に進む。`--break-system-packages`などでエラーを避けない
5. 入ったのに`typos --version`で`typos`のコマンドが見つからないときは、pipが`typos`を置いたディレクトリ（`pip show -f typos`で分かる）が`PATH`に無い。そのディレクトリを伝えて先に進む。`PATH`は変えない

## 指摘を扱う

- 指摘は、直す前に、出力のままユーザーに示す
- 直せる誤字は、ソースコードのコメントと、文書の文章の中の誤字に限る。指摘のあった行の中身を読んで、コメントや文章の中か、コードの中かを決める
- 次の4つは直さず、「確認してほしい点」としてユーザーに示す
  - コードの中の誤字（メソッド、変数、型などの識別子、文字列、文書のコードブロックとインラインコード、コメントの中でコードの名前を書いた箇所、コメントアウトしたコード）：直すと、定義や呼び出し元、設定のキー、APIのパスとの対応が崩れることがあるため。名前を変える範囲（定義と呼び出し元）と、辞書に登録して残す案を添える。利用者に見せる文章の文字列も、綴りを保つ必要がある文字列（設定のキーやパス）と見分けるには参照先を調べる必要があるので、ここに入れる
  - 誤字でない語（固有名詞、製品名、略語など）：辞書への登録を提案する
  - ファイル名：名前を変えると、参照している別の箇所が壊れることがあるため
  - 判断がつかない指摘：コメントか、コードの名前を書いた箇所かを決められないもの
- 直したら、直せる誤字が無くなるまでかけ直す。終了コードが1でも、残った指摘がすべて確認してほしい点なら先に進む
- 誤字を含む既存のパスや識別子を、文章の中でそのまま書いたときの指摘は、文章の誤字として直さない。確認してほしい点の名前を書いたものとして扱う
- 誤字でない語が指摘されたら、言い換えて避けない。辞書への登録をユーザーに提案する（「ユーザー辞書への登録」の節）

## ユーザー辞書への登録

確認してほしい点の語を次回から指摘させないときは、リポジトリのtyposの設定ファイルに登録する。このSkill、リポジトリのフック、CIが同じ設定ファイルを読むので、登録した語はどこでも通る。登録は、設定ファイルを直接編集して行う。

1. 確認してほしい点を示すとき、1つずつに扱いの選択肢を添える。選択肢は「直す」「辞書に登録して、次回から指摘させない」「今回は残す」の3つで、おすすめを1つ示す。「今回は残す」には、リポジトリのフックがtyposをかけていればコミットが止まることを添える
2. ユーザーが「辞書に登録」を選んだ語を足す設定ファイルを、次のように決める
   - typosの設定とは、`_typos.toml`、`typos.toml`、`.typos.toml`、`[tool.typos]`のある`pyproject.toml`、`[package.metadata.typos]`か`[workspace.metadata.typos]`のある`Cargo.toml`を言う
   - 指摘のあったファイルのディレクトリから、リポジトリ直下へさかのぼり、最初にtyposの設定が見つかったファイルに足す。typosは、ファイルのパスを渡されると、この設定だけを使い、親の設定は引き継がないためである
   - リポジトリ直下のtyposの設定にも足す。リポジトリ直下から`typos .`で起動すると、サブディレクトリの設定は読まれず、直下の設定だけが使われるためである。最寄りの設定がリポジトリ直下のものなら、1つに足すだけで済む
   - リポジトリの外のファイル（コミットメッセージやプルリクエストの下書きなど）の指摘は、リポジトリ直下の設定だけに足す
   - リポジトリ直下にtyposの設定が無ければ、`_typos.toml`を作る。ただし、typosの設定が既にあるディレクトリには、新しいファイルを作らない。typosは`_typos.toml`を優先するので、作ると既存の設定（`Cargo.toml`の辞書や除外など）が効かなくなるためである
3. 足す先の表は、語の種類で選ぶ。表の名前は、設定ファイルの形式に合わせる（`pyproject.toml`なら`[tool.typos.default.extend-words]`、`Cargo.toml`なら`[package.metadata.typos.default.extend-words]`）
   - 誤字でない語（固有名詞、製品名、略語など）：`[default.extend-words]`に、小文字の語をそのまま値にして足す（`lefthook = "lefthook"`）。大文字と小文字の違いを含めて、どこに出てきても通る
   - 綴りを保つ必要がある既存の名前（メソッド、変数、設定のキー、ファイル名）：`[default]`の`extend-ignore-re`に、その名前だけに一致する正規表現を足す。ファイル名は、拡張子を除いた名前にする。名前の部分だけが通り、同じ綴りの誤字が文章に出てくれば指摘される
   - 誤字そのものは、`[default.extend-words]`に足さない。どこに出てきても通るようになり、ほかの箇所の誤字を見逃すためである。足してほしいと頼まれたら、そのことを伝えてから足す
4. `extend-ignore-re`の正規表現は、TOMLのリテラル文字列（`'...'`）で書き、正規表現の特殊文字（`.`など）はエスケープする。`"..."`で書くと、`\.`がTOMLの誤りになる。`extend-identifiers`は使わない。typosは`-`と`.`で語を区切ってから照らし合わせるので、`-`や`.`を含む名前は通らないためである

   次の例の名前は書き方を示すためのもので、実際には誤字を含む名前を書く。

   ```toml
   [default]
   extend-ignore-re = [
     'fetchUserData',
     'service\.retryLimit',
     'legacy-config-loader',
   ]
   ```

5. `check_spelling.mjs`をかけ直して、登録した語が指摘されなくなったことを確かめる。`staged`で確かめるときは、足した設定ファイルを先にステージする。typosが設定ファイルの誤りで失敗したら（終了コード2で、typosの終了コードは78）、直してからかけ直す
