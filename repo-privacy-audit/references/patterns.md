# 検出の規則と誤検知の判定

`scripts/scan.mjs`の規則ごとに、探すもの、よくある誤検知、判定の目安をまとめる。
スクリプトが除外しているものは「除外済み」と書いた。除外済みの形は出力に現れない。

## 秘密情報

| 規則 | 探すもの | よくある誤検知と判定の目安 |
| --- | --- | --- |
| 秘密鍵 | `-----BEGIN ... PRIVATE KEY-----` | テスト用に作った鍵、本文を`...`で省いたドキュメントの例。テスト専用の鍵でも、公開すれば誰でも使えるので、どこで使っている鍵かを確かめる |
| サービスのトークン | AWS、GitHub、GitLab、Slack、Anthropic、OpenAI、Google、Stripe、npm、PyPI、RubyGemsの接頭辞つきの形 | ドキュメントの例やテストのダミー値。本物かどうかを、そのトークンを使って試さない。他人のトークンなら、試すこと自体が不正アクセスにあたりうる。形が正しければ漏えいとして扱い、無効化を勧める |
| JWT | `eyJ`で始まる3つの部分 | テストのフィクスチャ、jwt.ioの例。期限（`exp`）が過ぎていても、署名の鍵が同じなら問題が残る |
| URLに埋め込んだパスワード | `scheme://ユーザー:パスワード@ホスト` | `docker-compose.yml`の開発用データベース。ホストが`localhost`やサービス名なら重要度を低にしてある。プレースホルダー（`password`、`${...}`）は除外済み |
| パスワード・トークンらしい値の代入 | `password = "..."`、`token: ...`、`_authToken=...`など | テストの値、ハッシュ値、設定の例。値がプレースホルダー（`changeme`、`your-...`、`<...>`）のものと、引用符の無いコード（`SecureRandom.hex`）は除外済み |

## 個人情報

| 規則 | 探すもの | よくある誤検知と判定の目安 |
| --- | --- | --- |
| メールアドレス | 本文中のアドレス | noreplyのアドレスと例示用のドメイン（`example.com`など）、`icon@2x.png`、`git@github.com`は除外済み。個人向けのドメイン（Gmailなど）は重要度を高にしてある。取り込んだライブラリの作者の連絡先、公開を前提にした窓口（`security@`など）は問題ないことが多い |
| 作成者・コミッター・タグの作成者のメールアドレス | コミットとタグに記録されたアドレス | 会社のリポジトリで会社のアドレスを使うのは普通である。個人のリポジトリで個人のアドレスが混ざっていたら、noreplyのアドレスへの置き換えを提案する |
| 電話番号 | 日本の固定・携帯の番号、`+81`の形 | 日付やIDの並び、`090-0000-0000`のようなダミー。桁数が合わないものは除外済み |
| 郵便番号 | `〒`の付いた番号 | 会社の所在地のように公開しているもの |
| クレジットカード番号 | 検査桁（Luhn）が合い、ブランドの番号で始まる13〜19桁 | 長い数字のIDが偶然通る（数字の並びの約1割は検査桁が合う）。決済サービスのテスト用の番号は除外済み |
| ユーザー名入りのパス | `/Users/<名前>`、`/home/<名前>`、`C:\Users\<名前>` | 例として書いたパス。`runner`、`user`、`alice`のような一般的な名前は除外済み。残った名前が、持ち主の実名や別のアカウント名を示していないかを見る |
| 個人のクラウドストレージのパス | Dropbox、OneDrive、Google Drive、iCloud Driveのフォルダの下のパス | ストレージのAPIを扱うコード。手元のフォルダの構成を示すだけなので重要度は低 |
| 指定した語・正規表現 | `--term`、`--terms-file`、`--pattern`で渡したもの | 作成者の名前とメールアドレスにも当てる。作成者の一覧では、当たった部分を伏せる |

## 環境の情報

| 規則 | 探すもの | よくある誤検知と判定の目安 |
| --- | --- | --- |
| IPアドレス | IPv4の形 | 節の番号（`2.3.1.4`）、範囲の先頭（`172.16.0.0`）、ループバック、文書用の範囲、クラウドのメタデータサーバーは除外済み。プライベートのアドレスは重要度を低にしてある。SSRF対策の範囲の列挙やテストの値が多い。公開のアドレスは、自宅や自分のサーバーのものでないかを見る。値は伏せずに出す |
| 社内・内部向けのホスト名 | `.internal`、`.corp`、`.intranet`、`.lan` | `host.docker.internal`などの決まった名前は除外済み |
| 開発用の公開URL | `*.app.github.dev`、`*.<アカウント>.workers.dev`、ngrokなどのトンネル | CodespacesのURLはユーザー名を含み、ポートを公開している間は外から開ける。`workers.dev`のサブドメインはアカウント名を示す |
| AIのセッション・会話のURL | `claude.ai/code/session_...`、ChatGPTの共有URL | セッションのURLは本人しか開けない。AIを使ったことと作業の識別子が分かるだけなので、残すかどうかはプロジェクトの方針で決める。共有URLは誰でも開ける |

## ファイルの名前

過去に一度でも追加されたパスに当てる。今は消えていても、履歴から中身を取り出せる。

| 規則 | 探すもの | よくある誤検知と判定の目安 |
| --- | --- | --- |
| `.env`ファイル | `.env`、`.env.production`など | `.env.example`などの見本は除外済み |
| 鍵・証明書のファイル | `id_rsa`、`*.pem`、`*.key`、`*.p12`など | テスト用の証明書。Railsの`config/master.key`は本物の鍵である |
| 認証情報のファイル | `credentials.json`、`.netrc`、`.git-credentials`、`terraform.tfstate`、シェルの履歴など | 暗号化したファイル（`credentials.yml.enc`）は当たらない |
| トークンを書くことがある設定ファイル | `.npmrc`、`.yarnrc.yml`、`.docker/config.json` | トークンの無い設定だけのことが多い。中身の一致と合わせて見る |
| データのダンプ・記録 | `*.sqlite`、`*.db`、`*.sql`、`*.har`、`*.log` | スキーマだけの`*.sql`。HARファイルにはCookieと認証ヘッダーが入る |
| OSが作るファイル | `.DS_Store`、`Thumbs.db` | 中身にフォルダの名前が残る。重要度は低 |

## スクリプトが調べないもの

- 意味で判断する内容：法的な見解、第三者への評価、社内の事情、未発表の計画。文書とコミットメッセージを読んで探す
- バイナリのファイル：画像（スクリーンショットの写り込み、写真のEXIFの位置情報）、PDFとOfficeの文書のプロパティ（作成者名）、SQLiteのデータ。`exiftool`があれば`exiftool -a -gps:all -author -creator <ファイル>`で確かめられる
- 2,000,000バイトを超えるファイル（`--max-bytes`で変えられる）
- 実名。一般的な形が無いので、`--term`か`--terms-file`で渡す
- UTF-8以外の文字コード（Shift_JISなど）で書いた日本語

## プロジェクトの決まりを検査に直す例

| 決まり | 検査のしかた |
| --- | --- |
| コミットにモデル名を書かない | `--pattern 'Claude (Opus\|Sonnet\|Haiku)\|GPT-[0-9]'` |
| 実在のサイトのページをフィクスチャに入れない | テストのフィクスチャのHTMLと画像をファイルの一覧から拾い、中身を見る |
| 法的な見解を書かない | 文書とメッセージを読む。`--pattern '判例\|違法\|著作権法'`は手がかりにしかならない |

## 自分でコマンドを組むときの注意

- 語が入ったコミットと消えたコミットは`git log --all -S'<語>'`（正規表現なら`-G'<正規表現>'`）で探せる
- `LANG`が設定されていない環境では、RubyやPythonが標準入力をASCIIとして読み、日本語で失敗する。Rubyは`-E UTF-8`、Pythonは`PYTHONIOENCODING=utf-8`を付ける
- Windowsのコマンドプロンプトでは、`^`と`|`が特別な意味を持つ。正規表現は二重引用符で囲み、`^`は`^^`と書く。PowerShellでは単一引用符で囲む
